# My Understanding

ตอบแต่ละคำถามด้วยคำพูดของคุณเอง ไม่มีคำถามหลอกล่อ

เป้าหมายไม่ใช่คำตอบที่สมบูรณ์แบบ แต่เป็นคำตอบที่ตรงไปตรงมา เขียนเหมือนกำลังอธิบายให้เพื่อนที่ไม่เคยใช้ Express หรือ React ฟัง Assessment นี้ไม่มีวิดีโอ ดังนั้นเอกสารนี้คือจุดที่ความเข้าใจของคุณจะถูกประเมินจริง ๆ — ให้ทำอย่างตั้งใจ

อย่า copy จาก documentation, comment ในโค้ดของคุณ, หรือ AI output ถ้าไม่แน่ใจเรื่องไหน ให้เขียนเท่าที่คุณเข้าใจ และระบุว่าส่วนไหนยังไม่แน่ใจ

## Backend

**1. HTTP method แต่ละตัวในแอปของคุณหมายถึงอะไร — GET, POST, PUT or PATCH, และ DELETE? ทำไมเราถึงใช้ method ต่างกัน แทนที่จะใช้ POST สำหรับทุกอย่าง?**

*คำตอบของคุณ:*  
GET คือ การส่องดูข้อมูล เช่น ขอดูรายชื่อยางมอเตอร์ไซค์ทั้งหมดหน่อย

POST คือ เอาของใหม่ไปส่งหรือเพิ่มเข้าไป เช่น ยางรุ่นใหม่เข้า สั่งเพิ่มลงระบบ

PUT/PATCH คือ แก้ไขข้อมูลเดิมที่มีอยู่แล้ว เช่น ยางขึ้นราคา ขอแก้ราคาหน่อย

DELETE คือ ขอลบของทิ้ง เช่น ยางหมดสต็อกและเลิกขายแล้ว ลบทิ้งไปเลย

ทำไมไม่ใช้ POST อย่างเดียว เพราะว่า เหมือนเดินไปร้านอาหารแล้วบอกว่า ทำอาหารให้หน่อย โดยไม่บอกว่าอาหารอะไร คนครัว (Server) อาจทำให้งง การแยกแบบนี้ชัดเจนกว่า ว่าเรากำลังจะทำอะไรกับสินค้าชิ้นนั้น

---

**2. `express.json()` คืออะไร และจะเกิดอะไรขึ้นถ้าคุณไม่ใส่มัน?**

*คำตอบของคุณ:*
 ทำหน้าที่คล้าย ล่ามแปลภาษา เวลาเรากรอกข้อมูลจากหน้าเว็บส่งไปให้ Server มันจะมาเป็นก้อนข้อความ JSON เจ้าตัวนี้จะช่วยแปลงร่างให้มันกลายเป็นก้อนข้อมูลที่ JavaScript อ่านเข้าใจเก็บไว้ใน req.body ถ้าไม่ใส่ ล่ามไม่มา Server จะอ่านไม่รู้เรื่อง 

---

**3. `req.body`, `req.params`, และ `req.query` ต่างกันอย่างไร? ยกตัวอย่างจริงจาก API ของคุณสำหรับแต่ละตัว**

*คำตอบของคุณ:*
req.body: ของที่อยู่ในกล่องพัสดุที่เราแพ็คส่งมา 

req.params: ป้ายเลขที่บ้านหรือเลขที่แปะคาดหัว URL

req.query คือ คำถามต่อท้ายหลังเครื่องหมายคำถาม เอาไว้กรองหาของ 
---

**4. HTTP status codes คืออะไร? ระบุรายการ status code ทุกตัวที่คุณใช้ใน API และอธิบายว่าทำไมถึงเลือกใช้ในแต่ละสถานการณ์**

*คำตอบของคุณ:*
200 OK คือ ปกติ เรียบร้อยดี

201 Created คือ สร้างของใหม่สำเร็จแล้ว

400 Bad Request คือ ลูกค้าส่งข้อมูลมาผิดพลาด หรือข้อมูลไม่ครบ

404 Not Found คือ หาของชิ้นนั้นไม่เจอในระบบ 
---

**5. middleware คืออะไร? อธิบายด้วยคำพูดของคุณเองว่ามันทำอะไร พร้อมยกตัวอย่าง 1 อย่างจากโค้ดของคุณ**

*คำตอบของคุณ:*
มันคือ ด่านตรวจ ก่อนที่คนจะเดินเข้าไปถึงห้องข้างใน ต้องแวะให้ด่านตรงนี้ตรวจก่อน ถึงจะผ่านไปได้
---

**6. ทำไม order ของ middleware ใน Express ถึงสำคัญ? จะเกิดอะไรขึ้นถ้า order ผิด?**

*คำตอบของคุณ:*
เพราะ Express ทำงานเรียงคิวเหมือนการต่อแถวซื้อของ ถ้าเอาด่านตรวจแปลภาษา ไปไว้หลังห้องที่เขาใช้งานข้อมูลแล้ว ข้อมูลมันก็จะยังไม่ถูกแปล ทำให้ระบบพังเพราะอ่านไม่ทัน
---

**7. อธิบายทีละขั้นตอนว่าเกิดอะไรขึ้นบน server เมื่อมี POST request ถูกส่งไปที่ `/products`**

*คำตอบของคุณ:*
มีคนส่งคำขอมา -> ยามหน้าบ้าน (CORS) อนุญาตให้เข้า

ยามจดบันทึกประวัติลงสมุด (Logger)

ล่ามแปลงข้อมูลกล่องพัสดุให้เป็นภาษาที่ Server อ่านรู้เรื่อง (req.body)

วิ่งมาถึงห้องรับฝากของ เช็กดูว่ามีชื่อสินค้ากับราคาครบไหม

ถ้าครบ เอาไปเก็บใส่ตู้เย็น (Array) ของเรา

ส่งป้ายบอกว่า "สำเร็จแล้วนะ (201)" กลับไปหาคนกด
---

**8. CRUD คืออะไร? จับคู่แต่ละ operation กับ HTTP method และ route ที่คุณใช้ใน API**

*คำตอบของคุณ:*
Create ใช้คู่กับ POST

Read ใช้คู่กับ GET

Update ใช้คู่กับ PUT / PATCH

Delete ใช้คู่กับ DELETE
---

**9. API ของคุณตอบสนองอย่างไรเมื่อมีอะไรผิดพลาด — เช่น เมื่อ product ตาม ID ที่ระบุไม่มีอยู่จริง?**

*คำตอบของคุณ:*
ส่งสถานะ 404 Not Found

## Frontend & Integration

**10. CORS คืออะไร และแก้ปัญหาอะไร? ถ้าไม่ได้ config ไว้บน server ของคุณ คุณจะเห็นอะไรใน browser?**

*คำตอบของคุณ:*
ทำหน้าที่เป็นรั้วและระบบตรวจสอบ ของเบราว์เซอร์ ที่คอยกันไม่ให้เว็บคนละพอร์ตแอบมาหยิบของไป ถ้าเราไม่ได้เปิดใช้งาน CORS บน Server เวลารัน React จะไปขอข้อมูลจาก Server เบราว์เซอร์จะกั้นประตูทันที แล้วฟ้อง Error ใน Console ว่าติดปัญหา CORS Policy
---

**11. แอป React ของคุณ fetch ข้อมูลจาก API ที่ไหน? อธิบายว่า `useEffect` ในโค้ดนั้นทำอะไร และทำไมถึงเรียก fetch ตรง ๆ ใน component body ไม่ได้**

*คำตอบของคุณ:*
useEffect คือ คำสั่งให้ทำสิ่งนี้แค่ตอนเปิดหน้าเว็บขึ้นมาครั้งแรกเท่านั้น

ถ้าเราเอาไปวางไว้ข้างนอกลอย ๆ โดยไม่มี useEffect ทันทีที่ข้อมูลเปลี่ยน React มันจะสั่งให้โหลดใหม่วนลูปไม่รู้จบ จนเครื่องค้าง
---

**12. API base URL ของคุณถูกกำหนดไว้ที่ไหน และทำไมถึงเลือกเก็บไว้ตรงนั้น แทนที่จะ hardcode ไว้ในทุก fetch call?**

*คำตอบของคุณ:*
เพราะยุ่งยากตามไปแก้ทีละจุด ถ้าเราเขียน Hardcode ไว้ทุกไฟล์ ถ้าในอนาคตเปลี่ยนพอร์ตหรือย้ายบ้านไปขึ้นเซิร์ฟเวอร์จริงบนเน็ต เราต้องตามไปแก้เยอะมาก แต่ถ้าเก็บไว้ใน .env จะสะดวกกว่า
---

**13. เลือก action หนึ่งในแอปของคุณ — เช่น การลบ product อธิบายการเดินทางแบบครบวงจร (full round trip): เกิดอะไรขึ้นตั้งแต่ผู้ใช้คลิกปุ่ม ไปจนถึง request ไปถึง server จนถึงหน้าจออัปเดตด้วย list ใหม่**

*คำตอบของคุณ:*
กดปุ่ม Delete ที่หน้าจอ
ฟังก์ชันหน้าเว็บสั่งยิงสัญญาณ (fetch) แบบ DELETE พร้อมถือเลข ID สินค้าวิ่งไปหา Server
Server รับเรื่อง แกะดูว่าไอดีอะไร แล้วหยิบสินค้าตัวนั้นโยนทิ้งถังขยะจาก Array
Server ส่งกระดาษโน้ตตอบกลับมาว่า ลบออกแล้ว
หน้าจอ React เลยจัดการหยิบสินค้าตัวนั้นออกจากหน้าจอทันที ผู้ใช้เลยเห็นว่ามันหายไปเลยโดยไม่ต้องกดรีเฟรชหน้าเว็บใหม่
---

**14. แอปของคุณแสดงอะไรให้ผู้ใช้เห็นระหว่างที่ข้อมูลกำลังโหลด และแสดงอะไรถ้า fetch ล้มเหลว (เช่น server ไม่ได้รันอยู่)? ทำไมเรื่องนี้ถึงสำคัญ?**

*คำตอบของคุณ:*
เพื่อให้ประสบการณ์ที่ดีในการใช้งาน ถ้าเน็ตช้า แล้วหน้าเว็บนิ่ง ไม่มีอะไรเกิดขึ้น ผู้ใช้จะนึกว่าเว็บมีปัญหา แต่ถ้ามีคำว่า "กำลังโหลด" เขาจะได้รู้ว่าเกิดอะไรขึ้น
---

**15. หลังจากที่คุณ add, edit, หรือ delete product แล้ว list บนหน้าจอของคุณอัปเดตโดยไม่ต้อง refresh หน้าเว็บ อธิบายว่าทำไมถึงเป็นแบบนั้น — อะไรที่ทำให้ React re-render ด้วยข้อมูลใหม่?**

*คำตอบของคุณ:*
เพราะ ใช้ระบบความจำของ React (useState) พอเราสั่งเปลี่ยนแปลงข้อมูลปุ๊บ ตัวแปรความจำเปลี่ยน React จะรีบเอาข้อมูลใหม่ มาให้ดูทันที
---

**16. ส่วนไหนที่ยากที่สุดในการเชื่อมแอป React ของคุณเข้ากับ Express API และคุณทำอย่างไรถึงผ่านมันมาได้?**

*คำตอบของคุณ:*
การต่อข้อมูลเข้าหากัน

**19. อธิบาย bug หรือ error จริง ๆ ที่คุณเจอระหว่าง build โปรเจกต์นี้ 1 อย่าง คุณหาสาเหตุที่แท้จริงได้อย่างไร นอกเหนือจากการ copy error ไปถามใน chat?**

**20. เลือก route (backend) หรือ component (frontend) 1 อันที่ AI ช่วยสร้าง โดยไม่ย้อนกลับไปดู AI chat history อธิบายว่ามันทำอะไรและทำไมถึงทำงาน ด้วยคำพูดของคุณเอง**

*คำตอบของคุณ:*
Route สำหรับดึงข้อมูลสินค้าทั้งหมด GET /products
มันทำหน้าที่เป็นจุดรับคำขอ (Request) จากหน้าเว็บ React เวลาที่มีการเปิดหน้าจอขึ้นมาใช้งาน มันจะไปหยิบรายชื่อสินค้าทั้งหมดที่เราเก็บไว้ในความจำ (Array) แล้วแพ็กใส่กล่องส่งกลับไปเป็นข้อมูล JSON เพื่อให้หน้าบ้านเอาไปโชว์เป็นตารางสินค้าให้ผู้ใช้เห็น
